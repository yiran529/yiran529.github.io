GPU 架构与深度学习调度全解析（含面试高频题）

本文从 GPU 硬件架构、CUDA 执行模型、GPU 调度机制、PyTorch 软件层调度以及面试高频问答几个角度，系统梳理 GPU 在深度学习中的工作方式。

一、GPU 架构基础（面向深度学习）

1. CPU vs GPU 的设计哲学对比

维度 CPU GPU
设计目标 低延迟、复杂控制 高吞吐、大规模并行
核心数量 少，通常为 4–64 个 多，可达数千个 CUDA Cores
控制逻辑 复杂，例如分支预测、乱序执行 极简，强调并行吞吐
适合任务 串行、控制密集型任务 数据并行任务，例如矩阵、张量运算

深度学习的本质是大规模数值计算，例如矩阵乘、卷积等，这类计算天然适合 GPU 的大规模并行加速。

2. GPU 整体硬件结构（NVIDIA CUDA 架构）

2.1 逻辑层次结构

2.2 核心执行单元：SM（Streaming Multiprocessor）

SM 是 GPU 的核心执行单元，所有线程最终都会映射到 SM 上执行。

SM 的核心特性包括：

  • 包含 CUDA Cores、Tensor Cores 等计算资源；
  • 包含寄存器、Shared Memory 等存储资源；
  • 调度的最小硬件单位是 Warp；

  • 单个 SM 的理论最大驻留 Warp 数与 GPU 架构有关：

    • Kepler 架构：最多 48 个 Warp；
    • Maxwell 及以上架构，例如 Ampere、Hopper：最多 64 个 Warp；
  • 实际驻留 Warp 数会受到寄存器、Shared Memory、Block 大小等因素限制，通常低于理论上限。

3. CUDA 执行模型（核心）

3.1 Kernel / Grid / Block / Thread 层级结构

层级 含义 核心特点
Thread 单个执行流 最小执行实体
Block 线程块 Block 内线程可共享 Shared Memory
Grid Kernel 启动的整体单位 不同 Block 彼此独立，不能直接共享资源

3.2 Warp（硬件调度核心）

Warp 是 GPU 中最重要的硬件调度单位。

  • 1 个 Warp = 32 个线程；
  • NVIDIA GPU 固定以 32 个线程为一个 Warp；
  • GPU 以 Warp 为单位发射指令；
  • 同一 Warp 内线程执行相同指令，这种模式称为 SIMT（Single Instruction, Multiple Threads）；
  • 当同一个 Warp 内的线程走不同分支时，会发生 Warp Divergence，导致分支路径被串行化执行，从而降低性能。

4. GPU 内存层次结构

4.1 内存金字塔

从快到慢、从小到大依次为：

内存类型 访问速度 核心作用
Registers ★★★★★ 存储线程局部变量
Shared Memory ★★★★☆ Block 内线程共享数据
L2 Cache ★★★☆☆ 跨 SM 共享的缓存
Global Memory ★☆☆☆☆ 主显存，存储大规模数据

深度学习中的 GPU 优化核心是：减少 Global Memory 访问，尽量复用寄存器和 Shared Memory 中的数据。

5. GPU 运算部件 / 存储部件 / 逻辑架构的对应关系

理解 GPU 时，可以把它分成三层来看：

角度 典型概念 作用
逻辑架构 / 执行模型 Thread、Warp、Block、Grid、Kernel 程序员看到的 CUDA 抽象
运算部件 SM、CUDA Core、Tensor Core、Warp Scheduler 真正执行计算和调度的硬件
存储部件 Register、Shared Memory、L1/L2 Cache、Global Memory 存放计算所需的数据

三者的大致对应关系如下：

逻辑层次 主要对应的硬件部件 主要对应的存储部件 说明

Warp Warp Scheduler 调度的一组线程 各线程自己的 Register 1 个 Warp = 32 个线程，是 GPU 的最小硬件调度单位

Kernel 整个 GPU 执行的一次任务 Global Memory 作为主要输入输出区域 Kernel 启动后，GPU 将 Block 分配给 SM 执行

可以概括为：

1. Tensor Core 对应的逻辑层次是什么？

Tensor Core 是 SM 内部的矩阵计算硬件单元，不是单独对应某一个 Thread 或 Block。

更准确地说：

Tensor Core 主要对应 Warp 级别的协作计算。

也就是说，深度学习中的矩阵乘通常不是某一个 Thread 独立调用 Tensor Core 完成的，而是一个 Warp 中的多个线程协作发起矩阵乘加指令，例如 MMA / WMMA 指令，然后由 SM 内部的 Tensor Core 执行。

因此可以这样理解：

CUDA Core 更偏向普通标量 / 向量计算，而 Tensor Core 更偏向深度学习中常见的矩阵乘加计算。

2. SM 与 Block 是什么关系？

准确关系是：

一个 Block 只能被分配到一个 SM 上执行；一个 SM 可以同时驻留多个 Block，也可以在不同时间连续执行多个 Block。

所以从两个方向看：

方向 关系
一个 Block 对 SM 只能属于一个 SM，不能跨 SM
一个 SM 对 Block 可以同时执行多个 Block，也可以先后执行很多 Block

但要注意：这是从不同方向看的关系。整体上可以理解为：

GPU 会把很多 Block 分配给有限数量的 SM，每个 Block 只能落在一个 SM 上，而每个 SM 可以接收多个 Block。

Block 不能跨 SM 的原因是，Block 内线程可能需要共享 Shared Memory，并使用 __syncthreads() 同步；这些资源和同步机制都局限在单个 SM 内。

二、GPU 调度机制（硬件层）

1. Warp 调度：延迟隐藏的核心

GPU 不依赖复杂的乱序执行和分支预测来隐藏延迟，而是依赖大量 Warp 的快速切换。

典型过程如下：

  1. Warp A 发起 Global Memory 访问；
  2. Warp A 因访存延迟进入等待；
  3. Warp Scheduler 立即切换到就绪的 Warp B / C；
  4. 通过持续切换可执行 Warp，让计算单元尽量保持繁忙。

核心目标是：保持 GPU 计算单元持续工作，用 Warp 级并发掩盖访存延迟。

2. Occupancy（占用率）

Occupancy 指当前 SM 中活跃 Warp 数与 SM 理论最大 Warp 数的比值。

影响 Occupancy 的主要因素包括：

  • 每个线程使用的寄存器数量；
  • 每个 Block 使用的 Shared Memory 大小；
  • 每个 Block 中的线程数；
  • SM 可同时容纳的 Block 数和 Warp 数。

需要注意：

  • 高 Occupancy 不一定等于高性能；
  • 但过低 Occupancy 通常会导致性能瓶颈；
  • 对访存密集型任务来说，较高 Occupancy 有助于隐藏访存延迟；
  • 对计算密集型任务来说，瓶颈可能在计算单元或 Tensor Core，而不是 Occupancy。

PyTorch 中的 GPU 运算默认是异步执行的。

也就是说，Python 代码返回并不代表 GPU 已经完成计算。例如：

常见的隐式同步触发条件包括：

  • 调用 .item()；
  • 调用 .cpu()；
  • 调用 torch.cuda.synchronize()；
  • 某些需要把 GPU 结果传回 CPU 的操作。

这些操作会让 CPU 阻塞等待 GPU 完成，从而破坏异步执行带来的性能优势。因此，在训练和推理中应尽量避免不必要的同步。

5. 高级调度技术

5.1 计算与通信重叠（Overlap）

核心思路：

  • 将梯度计算放在计算 Stream 中；
  • 将 AllReduce 通信放在通信 Stream 中；
  • 让 GPU 计算和多 GPU 通信尽可能并行执行。

优势：减少通信等待时间，提高整体训练吞吐量。

在 PyTorch DDP 中，计算与通信重叠通常已经被默认集成。

5.2 CUDA Graph：减少调度开销

CUDA Graph 可以将一段固定计算流程录制下来，减少运行时 Kernel Launch 和调度开销。

适用场景：

  • 输入 shape 固定；
  • 模型计算图稳定；
  • 小 Kernel 较多，Kernel Launch 开销占比较高；
  • Transformer / DiT / MoE 推理等静态批量场景。

不适合场景：

  • 动态 Batch Size；
  • 动态控制流；
  • shape 经常变化的任务。

5.3 MoE 特有调度优化

MoE（Mixture of Experts，混合专家模型）的 GPU 调度挑战主要包括：

  • Token 到 Expert 的动态路由；
  • Expert 负载不均；
  • All-to-All 通信开销大；
  • 部分 GPU 或 Expert 可能过载，部分可能空闲；
  • Token 排序、分发、聚合会引入额外调度成本。

常见优化方向包括：

  • Expert 并行调度；
  • Top-k 路由优化；
  • Token Batching；
  • 动态负载均衡；
  • Stream-aware Expert Execution；
  • 减少跨 GPU All-to-All 通信开销。

四、核心总结（考试 / 报告友好）

GPU 通过 Warp 级调度、大规模并行和异步执行实现高吞吐。

深度学习框架，例如 PyTorch 和 TensorFlow，则通过 CUDA Stream、Event、DDP、CUDA Graph 等机制，在软件层最大化硬件利用率，并平衡计算与通信效率。

可以概括为：

GPU 硬件负责提供大规模并行计算能力；深度学习框架负责把模型计算、数据搬运和多卡通信组织成高效的异步执行流程。

五、面试高频问答（可直接背诵）

一、GPU 架构类

Q1：GPU 和 CPU 的核心区别是什么？为什么深度学习更适合 GPU？

标准回答：

CPU 以低延迟和复杂控制为目标，核心数量少但单核能力强；GPU 以高吞吐为目标，拥有大量简单计算核心，适合大规模数据并行任务。深度学习中的矩阵乘、卷积等计算高度数据并行，因此更适合 GPU。

加分点：

GPU 通过 SIMT 和 Warp 调度隐藏访存延迟，同时简化控制逻辑，把更多硬件面积用于计算单元。

Q2：什么是 SM？SM 在 GPU 中起什么作用？

标准回答：

SM（Streaming Multiprocessor）是 GPU 的基本执行单元，负责执行 CUDA Kernel。SM 内部包含 CUDA Cores、Tensor Cores、寄存器、Shared Memory、Warp Scheduler 等资源，所有线程最终都会映射到 SM 上执行。

加分点：

Kernel 中的一个 Block 只能在一个 SM 内执行，不能跨 SM 执行；不同 SM 之间相对独立，不能直接共享 Shared Memory。

Q3：什么是 Warp？为什么是 32 个线程？

标准回答：

Warp 是 GPU 的最小硬件调度单位，由 32 个线程组成。GPU 以 Warp 为单位发射指令，同一 Warp 内线程执行相同指令。32 是 NVIDIA 硬件设计中的权衡结果，兼顾 SIMD 宽度和调度复杂度。

加分点：

Warp Divergence 会导致分支路径串行执行，降低效率。一个 Block 通常由多个 Warp 组成，因此 Block 的线程数通常设置为 32 的整数倍。

Q4：什么是 Warp Divergence？如何避免？

标准回答：

Warp Divergence 指同一个 Warp 内的线程因为分支条件不同而执行不同路径，导致这些路径被串行化执行，从而降低性能。

常见避免方法包括：

  • 减少条件分支；
  • 重排数据，使同一 Warp 内线程尽量执行相同逻辑；
  • 使用 Mask 计算替代显式分支。

加分点：

Divergence 只影响单个 Warp 内部，不影响其他 Warp。对于 if-else 分支，不同路径都会被执行，只是未命中路径的线程处于闲置状态。

Q5：GPU 的内存层次结构是怎样的？

标准回答：

GPU 内存从快到慢、容量从小到大依次为：

优化核心是减少 Global Memory 访问，因为它延迟最高、带宽成本最大。

加分点：

Shared Memory 由程序员手动管理，灵活性高；如果每个线程使用寄存器过多，可能发生寄存器溢出，数据被写入更慢的内存中，显著降低性能。

二、GPU 调度与执行模型类

Q6：GPU 如何隐藏访存延迟？

标准回答：

GPU 不主要依赖乱序执行隐藏延迟，而是在同一个 SM 内同时驻留多个 Warp。当某个 Warp 等待内存访问时，Warp Scheduler 会切换到其他就绪 Warp 执行，从而掩盖访存延迟。

加分点：

足够的 Occupancy 是延迟隐藏的前提。如果活跃 Warp 太少，调度器没有足够的就绪 Warp 可以切换，访存延迟就会暴露出来。

Q7：什么是 Occupancy？高 Occupancy 一定好吗？

标准回答：

Occupancy 是 SM 中活跃 Warp 数与理论最大 Warp 数的比值，它反映了 GPU 隐藏延迟的潜力。但高 Occupancy 不一定等于高性能，因为性能还可能受计算单元、内存带宽、指令依赖等因素限制。

加分点：

Occupancy 受寄存器使用量、Shared Memory 使用量和 Block 大小限制。访存密集型任务往往需要更高 Occupancy 来隐藏延迟，而计算密集型任务即使 Occupancy 不高，也可能已经充分利用计算单元。

Q8：Block 为什么不能跨 SM 执行？

标准回答：

因为 Block 内线程需要共享 Shared Memory，并可能使用 __syncthreads() 进行同步。这些资源和同步机制都局限在单个 SM 内。如果一个 Block 跨多个 SM 执行，会带来很高的通信和同步成本。

加分点：

CUDA 原生不提供 Grid 级别的全局同步。不同 Block 之间通常通过多个 Kernel、Stream、Event 或全局内存间接实现同步。

三、深度学习框架（PyTorch）类

Q9：PyTorch 的 GPU 运算是同步还是异步的？

标准回答：

PyTorch 中的 GPU 运算默认是异步的。Python 代码返回并不代表 GPU 计算已经完成。只有当调用 .item()、.cpu()、torch.cuda.synchronize() 等操作时，CPU 才会阻塞等待 GPU 完成。

加分点：

异步执行可以实现 CPU-GPU 并行，例如 CPU 准备下一批数据时，GPU 同时执行当前计算。做 GPU 计时时必须显式同步，否则计时结果不准确。

Q10：什么是 CUDA Stream？有什么作用？

标准回答：

CUDA Stream 是 GPU 上的任务队列。同一 Stream 内的任务顺序执行，不同 Stream 之间的任务可以并行执行。它的核心作用是实现计算与通信重叠、多任务并行，从而提高 GPU 利用率。

加分点：

默认 Stream 是每个 device 上的默认任务队列。Stream 是 DDP 实现计算与通信重叠的重要基础。

Q11：如何实现计算与通信重叠？

标准回答：

可以将计算任务，例如梯度计算，和通信任务，例如 AllReduce，放入不同 CUDA Stream 中，并结合 NCCL 等异步通信库，使计算和通信尽可能并行执行。

加分点：

PyTorch DDP 已经默认集成了这类优化。实际实现时需要处理好任务之间的数据依赖，避免数据竞争或错误同步。

Q12：torch.cuda.synchronize() 的作用是什么？为什么不常用？

标准回答：

torch.cuda.synchronize() 会阻塞 CPU 线程，等待 GPU 上所有 Stream 的任务执行完成。它常用于调试和精确计时。

不常用的原因：

频繁同步会破坏 GPU 异步执行的性能优势，使 CPU 和 GPU 不能有效并行。

加分点：

stream.synchronize() 是更细粒度的同步方式，只等待指定 Stream 中的任务完成，比全局同步更灵活。

四、多 GPU / 分布式类

Q13：DDP 和 DataParallel 的区别是什么？

标准回答：

DataParallel 是单进程多线程架构，容易受到 Python GIL 和主 GPU 通信瓶颈影响；DDP 是多进程架构，每个 GPU 通常绑定一个独立进程，并使用 NCCL 进行高效通信，因此效率更高，是大规模训练的推荐方案。

加分点：

DDP 支持多机多卡训练，而 DataParallel 通常只用于单机多卡。DDP 通过 Ring-AllReduce 聚合梯度，通信效率更高。

Q14：AllReduce 是什么？为什么重要？

标准回答：

AllReduce 是分布式训练中用于梯度聚合的核心通信操作。它可以让所有 GPU 节点获得相同的梯度总和或平均值，是同步 SGD 的基础。

加分点：

Ring-AllReduce 是常见实现方式，避免了单点聚合瓶颈。通信成本是大规模分布式训练的主要瓶颈之一。

五、高阶加分题（MoE / Transformer 相关）

Q15：MoE 中最大的 GPU 调度挑战是什么？

标准回答：

MoE 中最大的 GPU 调度挑战是 Expert 负载不均和 All-to-All 通信开销。部分 Expert 可能处理大量 Token，而部分 Expert 可能空闲，导致 GPU 利用率下降；同时 Token 路由会引入跨 GPU 通信，进一步增加开销。

加分点：

可以通过 Expert 并行、动态负载均衡、Token Batching、Top-k 路由优化等方式缓解。Stream-aware 执行可以减少 Expert 调度延迟。

Q16：CUDA Graph 的作用是什么？适合哪些场景？

标准回答：

CUDA Graph 可以将一段 GPU 计算流程静态化，提前录制 Kernel 之间的依赖关系，从而减少 Runtime 调度和 Kernel Launch 开销。

适合场景包括：

  • 输入 shape 固定；
  • 模型结构和计算图稳定；
  • Transformer / DiT / MoE 推理；
  • 小 Kernel 较多、Kernel Launch 开销占比较高的任务。

加分点：

CUDA Graph 对动态控制流、动态 Batch Size 和频繁变化的 shape 不友好。它对小 Kernel 性能提升尤其明显，因为此时 Kernel Launch 开销占比较高。

终极总结句（强烈建议背诵）

GPU 通过 Warp 级调度和大规模并行隐藏延迟，而深度学习框架通过异步执行、CUDA Stream、通信重叠和分布式调度，在软件层最大化硬件利用率。
